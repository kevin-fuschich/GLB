SYSTEM
League operating record

Scope

  • Purpose
    Define the publishing standards for GLB records.
  • Audience
    Internal use. Public visibility is incidental.
  • Tone
    No explanations. No marketing. No winks.

File Types

  • League Record
    Standings, schedule, box scores, and system notices.
  • Team Record
    A team’s official record page (facts only).
  • Club File
    Identity material. Traditions. Artifacts. Separate from records. (forthcoming)

Naming Standard

  • Index
    index.html — silent directory of published records.
  • Box Score
    boxscore.html or boxscore_YYYY-MM-DD_TEAM_TEAM.html (optional later).
  • Standings
    standings.html — one file per week unless otherwise stated.
  • Schedule
    schedule.html — one file per week unless otherwise stated.
  • Team Record
    team-TEAMSLUG.html (example: team-san-pedro.html).
  • Club File
    clubs/TEAMSLUG.html (reserved). Not required for launch.
Team slugs are lowercase, hyphenated, no accents. Keep them stable once published.

Visual Standard

  • Typography
    Georgia for headings / summaries. Helvetica for dense tables.
  • Color
    One ink: navy. Greys for metadata. No secondary palette.
  • Layout
    Whitespace and alignment over decoration. Records must read cleanly on one screen.
  • Seal
    GLB seal appears on all published record pages.

Team Record Requirements

  • Header
    Team name + division + Team Record line.
  • Snapshot
    Record, runs, allowed, differential in a single quiet table.
  • Roster
    Active roster table (placeholder allowed during build phase).
  • Recent Games
    List recent results and link box scores when available.
  • Club Ref
    Include the line: Club file forthcoming.

Prohibitions

  • No lore
    Team Record pages do not contain narrative, history, or fan material.
  • No logos
    Team logos are reserved for Club Files (not Team Records).
  • No UI noise
    No icons, badges, gradients, or decorative widgets.
  • No claims
    No “about GLB” explanations. Records do not justify their existence.

Publishing

  • Indexing
    Only published files are listed on index.html.
  • Pending
    Use “not yet published” language instead of placeholders with fake detail.
  • Corrections
    When a record changes, update the file quietly. No changelog required.
